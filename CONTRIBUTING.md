# Contribuir

Gracias por querer mejorar USBGuardGo. Este repositorio distribuye **binarios, paquetes y documentación** de un producto propietario; el código fuente es privado.

## Qué se acepta

- **Reportes de errores** reproducibles, mediante la plantilla de bug.
- **Sugerencias de mejora** para la interfaz, la documentación o el empaquetado.
- **Correcciones de documentación** (erratas, enlaces rotos, instrucciones poco claras) abriendo un issue.
- **Reportes de seguridad** por el canal privado de [SECURITY.md](SECURITY.md), nunca en un issue público.

## Qué no se acepta

- Pull requests con código fuente, parches o ingeniería inversa.
- Redistribuciones del programa o de sus paquetes.
- Solicitudes de acceso al repositorio privado.
- Cambios de licencia o de marca.
- Issues con datos personales, números de serie reales o exploits públicos.

## Cómo reportar un error

1. Comprueba que no existe un issue abierto con el mismo problema.
2. Usa la plantilla **Bug**.
3. Incluye versión, distribución, escritorio, paquete y pasos para reproducir.
4. Adjunta un extracto del registro **redactado**.
5. Indica si ocurre siempre o de forma intermitente.

Un reporte claro y reproducible se puede investigar. Un «no funciona» sin contexto no.

## Cómo sugerir una mejora

Describe el problema antes de la solución: qué intentabas hacer, qué esperabas y qué ocurrió. Si propones un cambio de interfaz, explica a quién beneficia y cómo encaja con la filosofía del producto:

- Decisiones explícitas, nunca silenciosas.
- Bloqueo por defecto ante lo desconocido.
- Todo local, sin telemetría obligatoria.
- Claridad para usuarios no técnicos.

## Idioma

La documentación y los issues pueden escribirse en **español o inglés**. La interfaz se mantiene en ocho idiomas; las propuestas de traducción se estudian como sugerencias, sin acceso al código.

## Conducta

Este proyecto sigue el [Código de conducta](CODE_OF_CONDUCT.md). Sé respetuoso, concreto y paciente. No se toleran ataques personales, discriminación ni presión para obtener acceso al código.

## Licencia de las contribuciones

Al enviar un issue o una sugerencia, aceptas que el contenido pueda usarse para mejorar el producto sin obligación de compensación ni de atribución más allá de la que decidas indicar. No envíes material confidencial o de terceros sin permiso.

## Seguridad

No publiques vulnerabilidades. Usa [SECURITY.md](SECURITY.md).
